# Руководство по передаче проекта

Этот документ пишется заранее, постепенно — не в последний
момент перед продажей. Так меньше риск что-то забыть.

## Какие файлы входят в проект

Весь проект — одна папка (сейчас называется примерно
`lemma-site`). Полная структура — в PROJECT_STRUCTURE.md. Коротко:
один файл сайта (`index.html`), папка с картинками (`assets`),
папка с распечатками (`worksheets`), папка с документацией
(`docs`), история изменений (`CHANGELOG.md`).

## Как открыть текущую локальную версию

Никаких программ устанавливать не нужно.

1. Скачайте и распакуйте архив проекта.
2. Найдите файл `index.html`.
3. Дважды кликните по нему (или откройте через браузер: правой
   кнопкой → «Открыть с помощью» → любой браузер).
4. Сайт откроется прямо в браузере, интернет для этого не нужен —
   кроме одной детали: шрифт и произношение слов подгружаются
   из интернета, без сети сайт откроется, но будет выглядеть
   и звучать чуть иначе.

## Что пока хранится в браузере, а не «в проекте»

Прогресс конкретного ребёнка, лемы, открытые темы, купленные
предметы — всё это сохраняется в самом браузере на конкретном
компьютере (это называется «локальное хранилище браузера»,
по-английски localStorage). При передаче архива с файлами
это **не переезжает** вместе с файлами — новый владелец увидит
сайт «с чистого листа», без чужого тестового прогресса. Это
ожидаемо и не является потерей данных — тестовые данные и не
предполагались как что-то, что нужно сохранять.

## Окончательный состав персонажей

Луми, Эхо, Флип, Олли — четыре персонажа, без исключений и
добавлений. Если где-то в старых присланных материалах встретятся
другие имена (Мира, Нова, Орион) — это ошибочные подписи на
исходных файлах, не отдельные персонажи. Подробности —
`KNOWN_ISSUES.md`.

## Какие функции — заглушки (не выдавайте за готовые)

- **LUMA** — окно и кнопки настоящие, ответы — одна тестовая
  фраза, без разбора вопроса.
- **Регистрация** — просто имя и класс, без пароля и почты.
- Подробный список — FEATURES.md.

## Какие секреты нельзя включать в архив передачи

На сегодня в проекте **нет ни одного пароля, ключа доступа или
секретного кода** — сервер и внешние платные сервисы не
подключены, включать в архив пока нечего лишнего. Это правило
остаётся актуальным на будущее: как только появится сервер или
подключение к платному ИИ, ключи доступа **никогда** не должны
лежать внутри файла сайта — только в закрытой серверной части,
которой пока не существует.

## Какие сторонние аккаунты понадобятся новому владельцу

Сейчас — ни одного, сайт не завязан ни на один внешний платный
сервис. В будущем (когда появится сервер, домен, настоящий ИИ)
здесь появится список: где регистрироваться, что понадобится
оплатить.

## Как восстановить версию из резервной копии

1. Возьмите архив с нужным номером версии (например,
   `lemma-backup-v1.1.zip`).
2. Распакуйте.
3. Замените текущие файлы сайта файлами из архива.
4. Готово — откатились к этой версии полностью.

Резервные копии делаются перед каждым существенным изменением —
см. CHANGELOG.md, там же указано, какая копия к какой версии
относится.

## Технический аудит

Полная техническая проверка сайта проведена 30 июля 2026, версия
v1.4 — см. `FULL_SITE_AUDIT.md`. Три находки среднего приоритета
исправлены в версии v1.5 и подтверждены тестами. Визуальная
проверка на реальных устройствах ещё не проведена — используйте
`MANUAL_VISUAL_CHECKLIST.md`, чтобы сделать её самостоятельно.

## Где находится история изменений

`CHANGELOG.md` в корне проекта — единственное место, где ведётся
полная история версий (в `docs/` лежит только короткая ссылка
на него, чтобы не было двух версий истории — см. docs/README.md).

## Что стоит сделать перед реальной передачей (не сейчас)

- Закрыть открытые вопросы по правам на изображения персонажей
  (SALE_READINESS.md, раздел «Права на материалы»).
- Папки `assets/characters/*/source/` и `review-later/` содержат
  тяжёлые, неоптимизированные исходники (десятки мегабайт) — они
  нужны для истории и возможной пересборки, но не обязательны в
  архиве для конечного пользователя сайта. Решить, включать ли
  их в финальную передачу или хранить отдельно от рабочей копии.
- Проверить сайт на настоящем телефоне и в настоящем браузере —
  на этом этапе я проверял только расчётом, не глазами.
