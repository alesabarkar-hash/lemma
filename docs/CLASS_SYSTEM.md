# Система классов в ЛЕММЕ

Документ описывает, как в проекте устроен выбранный класс ученика.
Актуально с версии v1.31 (этап C5).

---

## 1. Источник правды

**Класс хранится ровно в одном месте: `u.cls` в активном профиле.**

Профили лежат в `localStorage` под ключом `lemma-users`. Класс — это
свойство ученика, а не экрана, поэтому:

- выбор переживает перезагрузку страницы;
- у каждого ребёнка на устройстве свой класс;
- класс уезжает вместе с профилем в коде переноса.

В памяти значение представлено переменными `curClass` и алиасами
`bkClass`, `drClass`, `dpClass`, `prClass`. Это **только представление**,
не хранилище. Все пять всегда синхронны.

### Три функции — и больше ничего

| Функция | Назначение |
|---|---|
| `setClass(c)` | **единственная** точка изменения класса из интерфейса: раскладывает значение по представлениям и пишет в профиль |
| `syncClassFromProfile()` | **единственная** точка восстановления: загрузка страницы, переключение профиля, импорт кода |
| `applyClass(c)` | внутренний помощник, **единственное** место, где присваиваются алиасы |

`setClass()` отклоняет класс, которого нет в `CLASSES`.

### Оставшиеся прямые присваивания

Их ровно три вида, все безопасны:

1. объявления переменных (`let curClass=2` и т.п.);
2. присваивания внутри `applyClass()`;
3. чипы классов на экране `s-learn`.

Третий пункт — диагностический резерв, недоступный пользователю с этапа
C2.5: ни одна кнопка интерфейса туда не ведёт. На месте оставлен
комментарий. **Если экран когда-нибудь оживят, это присваивание нужно
перевести на `setClass()`** — иначе там будет меняться только
`curClass`, а алиасы останутся на старом классе.

В наборе тестов есть постоянная защита (`C5.1i`), которая падает при
появлении любого нового прямого присваивания класса.

## 2. Критерии доступности: `classesWith(kind)`

Вопрос «есть ли для этого класса материал» решается в одном месте —
`classHasKind(c, kind)`, а разделы только спрашивают.

| kind | Класс считается имеющим материал, если… | Кто спрашивает |
|---|---|---|
| `topics` | есть хотя бы одна запись в `TOPICS[c]` | Практика, редактор профиля |
| `ready` | есть хотя бы одна **готовая** тема (`ready:true` и есть урок) | Учебный путь |
| `books` | есть главы в `BOOK[c]` | Учебник |
| `drills` | есть хотя бы один собираемый тренажёр (`drillAvailable`) | — |
| `deep` | есть тема с `LESSONS[id].adv` | Углублённый английский |
| `prints` | есть хотя бы один лист с `soon !== true` | Распечатки |

Важно про `prints`: карточки-заглушки (`soon:true`) **не делают класс
доступным по распечаткам**. У 3 класса две такие записи и ноль
скачиваемых файлов — раздел честно показывает пустое состояние.

`drillAvailable(c, id)` отвечает отдельно по каждому тренажёру:
словарный строится из словаря класса, а артикли и порядок слов требуют
собственных банков `ARTICLES` / `SENTENCES`.

## 3. Как добавить новый класс

1. Добавить номер в `CLASSES`, если его там ещё нет.
2. Завести темы в `TOPICS[N]`. Пока `ready:false` — тема видна в
   Учебном пути с меткой «В разработке» и не кликабельна.
3. Завести уроки в `LESSONS` для каждой готовой темы.
4. По мере готовности добавить: `BOOK[N]` (главы), `PRINTS[N]` (листы
   с реальными файлами, без `soon:true`), `ARTICLES[N]` и `SENTENCES[N]`
   (для тренажёров), блоки `adv` в уроках.

**Ничего фильтровать вручную не нужно.** Как только данные появятся,
класс сам появится в переключателях тех разделов, где для него есть
материал, а пустые состояния сами перестанут показываться —
`classesWith()` и `availableHere()` считают по фактам.

Единственное место с жёстким порогом — Практика: `renderDrills()`
содержит проверку `drClass!==2`. Открытие частичного набора тренажёров
для других классов — отдельное продуктовое решение (см. раздел 5).

## 4. Пустые состояния

Раздел, где для выбранного класса материала нет, показывает единый блок
через `emptyState(box, opt)`:

```js
emptyState(box, {
  what:  "Глав для 3 класса пока нет.",
  where: availableHere(3, "book"),
  note:  "Выбран 3 класс — учебник в этом разделе пока есть только для 2 класса.",
  actions: [
    { label: "Перейти в Учебный путь", go: "academy" },
    { label: "Открыть учебник 2 класса", setClass: 2, after: renderBook }
  ]
});
```

Действия передаются **данными**: `go` — переход, `setClass` — осознанная
смена класса по нажатию. Обработчики живут внутри `emptyState()`, разделы
их не дублируют.

`availableHere(cls, except)` собирает фразу «что при этом доступно» из
фактов и не упоминает раздел, в котором мы находимся.

### Правила
- класс профиля **никогда** не меняется автоматически;
- материал другого класса **никогда** не подставляется;
- сроки не обещаются;
- переход на другой класс — только по явному нажатию.

## 5. Известные ограничения 3 класса

| Раздел | Состояние |
|---|---|
| Учебный путь | 2 готовые темы (`g3_school`, `g3_food`) + 4 с меткой «В разработке» |
| Углублённый | 2 блока, работают |
| Учебник | глав нет вовсе (`BOOK[3]` пуст) |
| Распечатки | 2 записи, обе `soon:true` — скачать нечего |
| Практика | закрыта целиком |

**Почему Практика закрыта целиком, хотя словарный тренажёр собрать
можно.** У 3 класса 11 слов в словаре, а тренажёр рассчитан на 12
вопросов — будут повторы. Артикли и порядок слов собственного материала
не имеют вовсе. Открывать частичный набор — вопрос наполнения и
методики, а не фильтра интерфейса, поэтому решение отложено до этапа
наполнения 3 класса. `drillAvailable()` уже внедрена как техническая
основа для этого.

**Молчаливая подмена убрана.** Раньше `buildArticleDrill()` и
`buildSentenceDrill()` содержали `ARTICLES[cls] || ARTICLES[2]` и
отдавали материал 2 класса под видом чужого. Теперь при отсутствии
своего банка возвращается `null`, а `startDrill()` показывает честное
сообщение.

## 6. Неподдерживаемый класс в профиле

Класс 4–9 может оказаться в профиле двумя путями: сохранён старой
версией или приехал импортом кода. Поведение одинаковое и намеренное:

- приложение **не падает**, прогресс и лемы целы;
- класс **не переписывается молча** — это чужие данные;
- редактор профиля показывает подсказку «В профиле указан N класс, но
  материалов для него пока нет» и предлагает только реальные классы;
- `saveProfile()` не даёт сохранить неподдерживаемый класс — проверка
  идёт по списку, а не по наличию кнопок, и стоит **до** записи, поэтому
  введённые имя, фото и «о себе» не теряются;
- импорт кода переносит все данные, но показывает окно с выбором
  «Открыть профиль» / «Позже»;
- повторный экспорт до ручной смены сохраняет исходный класс.

## 7. Экран «Прогресс»

Показатели сверху относятся к **выбранному классу**, как и таблица тем
под ними. Общий итог — отдельной строкой «Всего за всё время».

`realTopicTotals(cls)` считает по одному классу, `realTopicTotals()` —
по всем. Это одна функция с необязательным аргументом, поэтому «в этом
классе» и «всего» не могут разъехаться.

Считаются только реальные темы из `TOPICS`. Служебные записи `PROG`
(`{topic}_l1`, `_l2`, `_check`, `_adv`, `_fix`, drill-идентификаторы)
темами не считаются — иначе одна тема с под-уроками считалась бы за
три-четыре, а её слова складывались бы дважды.
